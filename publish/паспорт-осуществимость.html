Вердикт

Контур паспорта подтверждён. Автоматизировать нужно не 344 подписанных поля, а 76 исходных колонок листа «Квартирография (жилое)». Формулы (комнатность, площади, коэффициенты, цена) уже в файле — парсер пишет только значения.

Пилот по штампам квартир из векторного PDF можно запускать сразу. Полный объём 76 полей упирается в IFC-выгрузку и письменные правила ЭНКО, не в архитектуру матрицы.

Эталон xlsm

19 листов, VBA на месте, 14,5 МБ. Целевой лист 5 202 × 349, данные с 8-й строки, все 1 054 квартиры с ГП=10. Писать только в исходные колонки: H–P и блок коэффициентов — формулы.

Замечание по шаблону: группа R6 «Лоджия 1» подписана в R7 как «Лоджия 2». Маппинг колонок вести по строке 6, не слепо по строке 7.

Первый спринт

  1. Копия шаблона ГП-10 без строк ГП=10 — не затирать эталон.
  2. Парсер штампов К-1/К-2/К-3 → ~490 строк.
  3. Привязка подписей помещений к квартире.
  4. Лист «требует проверки».
  5. Запрос IFC: IfcSpace + этаж + номер.

Риски, подтверждённые файлами

  • IFC в тестовой папке нет — только .rvt.
  • Свода правил 28 полей нет; в файле есть выпадающие списки и коэффициенты.
  • ГП-10 нельзя использовать как метрику точности для Айвазовского.
  • Номера лотов уже читаются со штампов PDF — запасной путь паспорта работает.

Оценка 184 ч остаётся реалистичной, если ЭНКО отдаёт IFC с помещениями и правила классификации. Без этого проект сужается до PDF-парсера и ручной доводки 28+8 полей — всё ещё окупаемо на корпусе, но не «один прогон → готовая матрица».
